## 1. 支持矩阵

三个平台的**产品形状不同，因为桌面不同**：同一个能力在一个平台上可能没有对应物，或者需要一个完全不同的做法。

| 能力 | Windows | macOS (Apple Silicon) | Linux (Wayland) |
|---|---|---|---|
| 远程控制（键鼠注入） | ✅ `SendInput` / `SendSAS` | ✅ CGEvent | ✅ libei |
| 观看模式 | ✅ | ✅ | ✅ |
| 屏幕采集 | DXGI Desktop Duplication | ScreenCaptureKit | portal + PipeWire |
| 编解码 | Media Foundation | VideoToolbox | libavcodec（NVENC / x264；VA-API 🔬） |
| 多显示器 | ✅ | ✅ | ✅（Wayland；仅限共享对话框里勾选的屏） |
| 剪贴板（文本 + 图片） | ✅ | ✅ | ✅（每次连接要授权） |
| 音频（被控端声音回传） | WASAPI 环回 | ScreenCaptureKit 环回 | PulseAudio |
| 文件传输 | ✅ | ✅ | ✅ |
| 远程终端 | ✅ ConPTY（PowerShell / cmd） | ✅ PTY（登录 shell） | ✅ PTY（登录 shell） |
| 远程摄像头 | ✅ Media Foundation | ✅ AVFoundation | ✅ portal + PipeWire（真机验证） |
| 无人值守（固定密码） | ✅ 登录前也在线（服务） | ⚠️ 仅登录后（host 包用 LaunchAgent，client 用登录项） | ❌ 无法无人值守操作，见下 |
| 登录界面 / 登录前访问 | ✅ 服务换 Agent 接管安全桌面 | ❌ 没有对应物 | ❌ 没有对应物 |
| 快速用户切换 / 多用户 | ✅ | ❌ 一个进程一个用户 | ❌ 一个服务一个用户 |
| Ctrl+Alt+Del | ✅ `SendSAS` | ❌ 没有对应概念 | ❌ 没有对应概念 |
| 防休眠（Keep-Awake） | `SetThreadExecutionState` | IOKit 电源断言 | logind `Inhibit` |
| 密钥存储 | DPAPI | Keychain | 0600 文件（威胁模型见 [系统设计](../design/README.md) 的“安全边界”一节） |
| H.265 | ❌ 未实现 | ❌ 未实现 | ❌ 未实现 |
| 隐私屏 | ❌ 未实现 | ❌ 未实现 | ❌ 未实现 |

**读这张表的规矩**：⚠️ 表示"可用但有限制"（例如 macOS 的无人值守只在登录后可用），🔬 表示"代码在但没在
真机上验证过"（例如 Linux 的 VA-API 硬件编码），❌ 表示"这个平台上没有对应物或没做"。三者不一样——
⚠️ 能用但有边界，🔬 可能一跑就通，❌ 做不了。被控端**不会假装成功**：没有的能力，或被控端没有授予的能力，控制端界面上根本不显示
相关按钮（例如 Ctrl+Alt+Del），而不是显示一个按下去没反应的按钮。

### 被控端的形态

| | Windows | macOS | Linux |
|---|---|---|---|
| 被控端是什么 | LocalSystem 服务 + 用户会话里的 Agent（服务拉起的辅助进程，真正采集屏幕、注入输入的是它） | 用户会话里的 app（client，或独立的 host-only app） | 图形会话里的 `systemd --user` 服务 |
| 为什么是这个形状 | Session 0 采不到屏，必须拆出一个在交互会话里干活的 Agent | 没有 Session 0，root 的 LaunchDaemon 拿不到屏幕录制权限，所以只能是一个用户会话里的 app；host 包把这个 app 做成无窗口、只被控的形态 | portal 只在该会话内应答，所以宿主自己就是采集和注入的那一方 |

**只装了客户端包、没有 host 服务的机器**，被控端就在客户端这个进程里运行（界面上写"被控端在本进程内运行"），
主页与「高级设置」里的"本机控制端代码"是同一个。装了 host 服务（Windows 的服务、Linux / macOS 的 host 包）之后，
客户端只负责发起连接：主页显示的是服务的设备代码，「高级设置」里的"本机控制端代码"是另一个——这台机器连出去
时用的是后者。

Windows 的形态最复杂，因为它要跨越用户桌面 / 登录界面 / UAC 三个桌面：

- 服务（LocalSystem）本身**不采集屏幕、不注入输入**，只负责连接、鉴权、授权和转发；屏幕和输入由当前控制台
  会话里的 Agent 完成。桌面切换到登录界面 / 锁屏 / UAC 时，服务换上另一种 Agent（用户令牌 / winlogon 的
  SYSTEM 令牌），控制端画面不中断。注销、登录、快速用户切换、Agent 崩溃同理。
- Ctrl+Alt+Del 不能用按键注入，只能由服务调用 Windows 的安全注意序列接口（`SendSAS`；安装脚本会打开所需策略
  `SoftwareSASGeneration`）。
- 客户端检测到服务后，设备代码和临时密码显示的是服务的那一份；客户端自己只负责发起连接。
  `--HostMode standalone` 可忽略服务，直接用客户端当被控端（只能控制用户桌面，看不到登录界面和 UAC）；
  这个开关三个平台都生效，见“连接”一节末尾的命令行开关。

另外两个平台都没有这一层拆分，所以也没有这些机制：macOS 与 Linux 上不存在"登录前访问"，因为采集与注入 API
本身就只在用户图形会话里可用。

### macOS (Apple Silicon)

最低系统版本是 **macOS 26 (Tahoe)**，成因见 [平台移植总览](../ports/README.md#3-macos-apple-silicon) 的“最低系统版本是 macOS 26”。
原生辅助库由 `native/macos/build-native.sh` 自动构建（构建平台项目时触发）；
首次构建前需运行 `native/macos/fetch-libmsquic.sh` 暂存 MsQuic。

与 Windows 的能力差异（没有 Ctrl+Alt+Del、没有登录界面 / 登录前访问、一个进程只服务一个用户、H.265 与隐私屏未实现）
都已在上面的矩阵里，不再重复。host 包是独立的无窗口 app，**没有服务，也就没有登录前访问**。

**需要人工做的一件事：**

- **屏幕录制 / 辅助功能 / 摄像头授权**：首次使用要在「系统设置 → 隐私与安全性」里人工授予，
  而授权是**按签名身份**记录的——开发构建换了签名就要重新授权一次。

### Linux

**先说不会工作的部分：**

- **登录界面 / 登录前的远程访问**：GNOME 的登录界面是另一个用户、另一个 VT，私有用户会话既看不见也驱动不了。
  Windows 上能换 Agent 接管安全桌面，这里**没有对应物**——这是相对 Windows 的真实能力回退。
  （Ctrl+Alt+Del 与多用户同样没有对应物，见上面的矩阵。）
- **剪贴板**：已实现，两个方向都在本机端到端验证过（发布、读取、以及"本机复制后同步过去"的触发）。
  前提是桌面愿意授权：portal 把它挂在一条远程桌面会话上，每次连接都要点一次同意，和键盘鼠标是同一次。
- **摄像头**：已在 Ubuntu 26.04 + 4K USB 摄像头上真机验证（MJPEG 1280×720@30 → NV12 → H.264，
  硬件 NVENC，端到端延迟约 5 ms）。走 portal 的摄像头节点 + PipeWire，与采集屏幕同一套机制。
  **后台宿主不能弹出 portal 的摄像头授权框**（GNOME 只允许有焦点的应用弹），所以需要在客户端的
  「高级设置 → 安全 → 摄像头权限」里允许一次，或运行
  `RemoteDesktop.HostService --camera-access allow`；允许后控制端才能列出并使用本机摄像头，可随时撤销。
  未允许时控制端会直接看到"被控端未允许摄像头访问"，而不是"没有摄像头"。
- **光标形状与位置**：本机实测收不到 portal 的光标元数据（`cursor_mode=Metadata` 授权成功，但 PipeWire 流里
  始终没有 `SPA_META_Cursor`）。被控端会记一条警告然后照常出帧，控制端只能画自己最后知道的那个指针。
- **X11 会话**：只在 Wayland 上验证过。portal 路径在 X11 下大概率也能用，但不作承诺。

**需要什么：**

- Wayland 桌面加一个 portal：`xdg-desktop-portal-gnome`（GNOME）、`xdg-desktop-portal-kde`（KDE）或
  `xdg-desktop-portal-wlr`（wlroots 系）。**没有 portal 就什么都共享不了**——这是被控端唯一的入口。
- 编码用 `libavcodec`，有 GPU 就用硬件编码器（NVENC / VA-API），没有就回落 x264。装了哪个、有没有回落，
  都在被控端日志里。
- 采集走 PipeWire，输入走 libei（**不需要 `/dev/uinput` 这种机器级特权**）。两者都随 `.deb` 一起声明为依赖。
- 被控端是一个 `systemd --user` 服务，**没有 Agent**——见上面的"被控端的形态"。

### 授权的差别——Linux 上这条最影响使用

**共享屏幕授权一次就记住了，控制屏幕每次都要重新授权。**

不是实现取舍，是 portal 的规定：远程桌面会话不允许持久化（请求 `persist_mode` 会被整条拒绝，报
"Remote desktop sessions cannot persist"）。所以一台无人值守的 Linux 机器可以**被观看**，但**没人坐在跟前
就没法被操作**。这是相对 Windows 的真实差异，做方案时要按这个来——**要在无人值守的机器上被操作，
只能用 Windows 的被控端**。同理，Linux 上的固定密码并不能让控制变成无人值守。

反过来也有一条好处：**polkit 的提权提示渲染在用户会话里**，所以和 Windows 的安全桌面不同，**它是能被采集到的**。

### 先确认这台机器能不能用

三个平台的客户端都带一个自检开关，把该问的一次问完：

```bash
remotedesktop --self-check                                           # 客户端（Windows 是 RemoteDesktop.Client.exe）
/usr/lib/remotedesktop-host/RemoteDesktop.HostService --self-check   # Linux 被控端
```

Linux 上它检查数据目录、QUIC、会话类型、会话总线、运行时目录、portal（顺带答摄像头有没有）、显示布局、
PipeWire、libei、libavcodec 版本、可用的 H.264 编码器；Windows 上只报告数据目录和传输层；macOS 上先看进程是否在已签名的 `.app`
里以及签名身份、QUIC 传输和屏幕录制 / 辅助功能 / 摄像头三项授权（缺屏幕录制或不在 `.app` 里算不通过，其余两项只提示），
再按客户端实际的组装方式核对各平台端口是否注册，并逐项做真实探测（钥匙串读写、显示器与抓帧、防休眠、剪贴板、
摄像头、音频、视频编解码往返、录像、登录项、输入注入、受保护目录、终端与文件权限）。自检**不打开摄像头**，
但**不是没有副作用**：Windows 与 Linux 只有数据目录的可写探测（创建目录、写一个 `.writable` 空文件后立刻删除）；
**macOS 还会**访问桌面 / 文稿 / 下载三个受保护目录（第一次会弹出系统的文件夹授权框，这是故意的）、向钥匙串
写一条临时密码再删除、用临时剪贴板做一次文本与图片往返、写一个临时 `.mp4`、创建电源断言并注入一次指针事件。
所以"在一台还没授权过的机器上照样能跑"只对 Linux / Windows 成立；macOS 至少要在已签名的 `.app` 里运行，
报告才有意义。有必需项不通过时退出码是 1。

`--output <文件>` 可以把整份报告同时写进文件。macOS 通过 `open -a` 启动时会丢掉命令行参数，这时改用环境变量：
`RD_SELF_CHECK=1` 让每次启动都只自检然后退出，`RD_SELF_CHECK_OUTPUT=<文件>` 指定报告写到哪里（效果等同于加了
`--output`；只有客户端读这两个变量，被控端服务不读）。**只要 `RD_SELF_CHECK` 非空就会触发自检，`0` 和 `false` 也一样**，
所以不能靠把它设成 `0` 来关闭；用完要把两个变量都取消（unset，例如 `launchctl unsetenv`），
否则每次启动该应用都不再打开窗口。

**被控端更需要它**——portal、PipeWire、libei 和显示都是它在用，而只装被控端的机器上未必有客户端可跑。

## 2. 连接

客户端主窗口左侧是三个页面：

- **主页**：本机设备代码和临时密码、发起连接。
- **设备列表**：最近连接过的设备，选中后显示它的设备代码和各项功能。
- **高级设置**：固定密码、服务器与托管信息、数据目录。

在主页输入另一个客户端显示的设备代码和临时密码，选好连接方式，点击连接，状态栏会显示"直连 / 中继"和延迟。

Windows 与 Linux 上还可以用 `remotedesktop://` 链接把设备代码带进来，省掉手输：

```text
remotedesktop://connect?code=902226105
remotedesktop://902226105
```

两种写法都接受，代码里的空格、连字符和百分号编码都可以。点开链接会打开客户端并把设备代码填好；**它不会自动连接**
——链接可能来自浏览器、聊天消息或邮件，所以密码由你输入、"连接"由你点。链接里没有密码，也没有用户名的位置。
客户端已经在运行时，链接会交给那个窗口，不会另开一个（两个控制端用同一个身份会被信令服务器互踢）。
**macOS 尚未注册这个协议**：LaunchServices 通过 Apple Event 投递 URL，客户端还没接这条通道，点了没有反应。

设备列表里每台设备前面有一个在线状态圆点：实心绿表示在线，实心灰表示离线，**空心表示状态未知**
（服务器没有回应查询，例如它是一台旧版服务端）。这个状态由服务器提供，仅供参考，连接能否成功仍以实际结果为准，
它也不会禁用任何按钮。

命令行开关：`--Transport:ForceRelay true` 强制走中继，`--Transport:RendezvousUri wss://<服务器>:5080/ws`
连接其他服务器（非回环地址用 `ws://` 时还要加 `--Transport:AllowInsecureSignaling true`，只限隔离实验网），
`--DataDirectory <目录>` 换一套设备身份，`--HostMode standalone` 不委托给本机已装的 host
服务、由客户端这个进程自己托管被控端（Windows、macOS、Linux 都生效）。

## 3. 远程桌面窗口

窗口顶部显示分辨率、帧率、码率、编码器、解码耗时、画面延迟（采集到解码完成，仅在双方时钟同步时准确）和 RTT。

- **被控端指针**：画面里不含鼠标，客户端把被控端真实的指针形状和位置画在叠加层上（控制时隐藏本地指针，
  观看时保留）。
- **多显示器**：被控端有多个显示器时，工具栏出现下拉框可切换；显示器拔插时自动回落到主显示器。
  Linux（Wayland）有一处平台差异：被控端只能串流操作员在屏幕共享对话框里勾选的那块屏，没有"请求某块显示器"的
  协议调用。若被控端只共享了一块而这里选了另一块，画面会是**被共享的那块**，工具栏随之显示它的名字；
  共享了多块而选了不在其中的一块，会直接报错并列出已共享的尺寸，需要被控端重新共享。
- **剪贴板**：文本和图片双向同步，只同步连接之后的变化；观看模式下不开放。
- **音频**：被控端正在播放的声音（Windows 是 WASAPI 环回，Opus 编码）在控制端播放，可静音；
  输出设备切换后自动跟随；观看模式下仍可听。
- **被控端的权限**：被控端界面列出正在控制本机的人，可随时点"仅观看"（立即关闭其输入、剪贴板等通道，
  控制端界面随之变化）或"断开"。
- **录制**：工具栏的"录制屏幕"把当前画面存成 MP4，再点一次停止并保存；摄像头窗口的"录制摄像头"同理。
  三个平台都写到系统「视频」文件夹下的 `RemoteDesktop` 目录（`Screen_<时间戳>.mp4` / `Camera_<时间戳>.mp4`），
  目录不存在时会自动创建；Linux 上「视频」文件夹随系统语言而定（例如 `~/视频` 或 `~/Videos`）。
- **控制授权**：Linux 被控端还要经桌面的 portal 授权。系统对话框弹出时，控制端顶部显示"已请求被控端
  授权控制"；被控端需要在对话框里打开"允许远程交互"再点"分享"。如果被拒绝或对话框被关掉，控制端显示
  "被控端未允许控制：当前只能观看"并给出"重试授权"按钮；允许后横幅消失、键鼠恢复，不必重新连接。
  Windows / macOS 没有这层单独授权，不显示该提示。

> 测性能请用 Release 构建（`-c Release`），Debug 构建的颜色转换慢约 10 倍。

## 4. 文件传输

工具栏的"文件"按钮（观看模式或被控端收回权限后不显示）打开双栏文件管理器：左边本机，右边被控端。

- 选中文件或文件夹后点"上传 →"/"← 下载"，文件夹会递归复制；也可以把资源管理器里的文件直接拖到右侧。
  "文件已存在时"可选覆盖、跳过或保留两者（重命名为 `名称 (1).扩展名`）。
- 传输列表里每项可暂停、继续、取消；失败的可以重试。最多同时传 3 个，其余排队。暂停、网络中断、
  关闭窗口都不会丢进度（取消才会丢弃）。
- **断点续传与校验**：没传完的文件以 `<目标名>.<大小>-<修改时间>.rdpart` 保存在目标文件夹，
  下次从已有长度继续（大小或修改时间变了就不会误续）。被控端会把这些残片记在一份清单里
  （`partial-files.log`），**超过 7 天没人回来续传的自动删掉**（只清扫清单里以 `.rdpart` 结尾的绝对路径）——否则对方每放弃一次尝试就在你的文件夹里
  留一个文件。传完后比较整个文件的 xxHash64，一致才改成目标名并设置修改时间，所以目标名下永远不会出现
  写了一半的文件；校验不一致时丢弃临时文件并自动从头重传一次。取消会删除临时文件。
- **安全**：Windows 上文件操作由 Agent 以登录用户的身份执行，从不以 SYSTEM 执行；被控端只有登录界面 / UAC 可用时
  一律拒绝。路径必须是绝对路径，拒绝设备路径（`\\.\`、`\\?\`）、NTFS 备用数据流和 `CON`、`NUL` 等保留名，
  `..` 先解析再检查。**当前版本没有"把可访问范围限制到指定目录"的配置项**：被控端不限制根目录，登录用户能访问的
  基本都可以访问；没配根目录时仍然拒绝 UNC 网络共享（Windows）和 `/proc`、`/sys`、`/dev`（Linux / macOS）。观看模式由被控端拒绝文件通道。会话 ID、操作类型和路径写入被控端日志作为审计记录：Windows 上是
  Agent 日志（`agent-user-*.log`，登录界面 / UAC 桌面是 `agent-secure-*.log`）；Linux 和 macOS 没有 Agent，
  记在被控端进程自己的日志（`service-*.log`）里；独立客户端模式（`--HostMode standalone`）没有文件日志。
- 服务到 Agent 的文件通道是无损转发：带背压、不丢帧、不因为 Agent 被替换而续传到另一个 Agent；
  Agent 丢失时传输中止，重试即可续传。

## 5. 远程终端

工具栏的"终端"按钮（观看模式或被控端收回权限后不显示）打开终端窗口：每个标签是被控端上的一个 shell，
可以同时开多个。

- **Windows**：被控端用 Windows 伪控制台（ConPTY）运行 PowerShell 7（有则用）、Windows PowerShell 或 cmd，
  窗口顶部可选 shell。shell 由 Agent 以登录用户的身份启动，从不以 SYSTEM 启动；只有登录界面 / UAC 可用时拒绝。
  shell 及它启动的子进程放在作业对象里，关闭标签、断开连接或 Agent 退出都会把它们一起结束。
- **Linux / macOS**：被控端用 PTY 启动**登录 shell**（`-l`，读和本机终端相同的配置文件），可选的是账号自己的 shell
  （取自 `$SHELL`）以及 bash、zsh、fish、sh 中本机存在的那些；工作目录是用户主目录。
- 控制端只能选被控端列出的名字，不能指定程序路径；同一台被控端最多同时开 8 个终端。打开、退出和关闭记入被控端日志
  （Windows 是 `agent-user-*.log`，Linux / macOS 是 `service-*.log`），不记录键入内容。
- 终端窗口是自带的 VT 模拟器：xterm 兼容的光标与滚动区、
  16 / 256 / 真彩色、粗体斜体下划线、备用屏幕（vim、less、nano 用）、滚动缓冲（5000 行）、
  宽字符（中日韩和 emoji 占两格）、括号粘贴、鼠标上报（vim、htop 用）、窗口大小随窗口变化。
  已用真实的 PowerShell（含 PSReadLine 的历史与行编辑）、vim、less、nano 验证。
- **终端在两种主题下都用自己的深色配色**：ANSI 的 16 色是按深色背景定的，搬到浅底会失去对比，所以画面与
  状态栏保持深色，而窗口边框、标签栏和其余界面跟随系统主题。这是有意的选择，不是漏掉浅色主题。
- 操作：选中文字**不会**自动复制，要复制得再按 Ctrl+Shift+C、Ctrl+Insert，或有选中时按 Ctrl+C（双击选词，
  三击选行）；右键有选区时复制、没有选区时粘贴；Ctrl+V、Shift+Insert、中键粘贴**控制端**剪贴板的内容；Shift+PageUp / PageDown 或滚轮翻看历史；程序开启鼠标上报时按住
  Shift 可以照常选中文字。
- 限制（Windows）：被控端锁屏、注销或切换到安全桌面时 Agent 会被替换，终端随之结束（窗口会提示，重新开一个即可）。
  Linux / macOS 没有 Agent，锁屏或会话结束会直接结束终端。

## 6. 远程摄像头

工具栏的"摄像头"按钮打开摄像头窗口：选被控端的摄像头和分辨率（最高 30 fps；只提供 60 / 120 fps 模式的摄像头或采集卡，被控端会选它最低帧率的模式并丢帧到 30 fps 发送，窗口里显示的也是 30 fps），点"开始"即可看到画面，
窗口底部显示分辨率、帧率、码率、编码器和延迟。

- **常规远程功能**：作为标准功能随控制会话开放（和文件传输、终端一样）；观看模式下不开放。
- **被控端始终看得到且可随时关停**：有人正在通过摄像头看时，被控端界面在该连接下显示"正在使用本机摄像头"，
  并有"关闭摄像头"按钮（只关这一个连接的摄像头，连接继续）。摄像头自带的指示灯和 Windows 的摄像头使用
  提示也会亮。
- 采集用 Media Foundation（USB 摄像头、笔记本内置摄像头、虚拟摄像头都行），摄像头给什么格式（MJPEG、
  YUY2、NV12）都转成 NV12，之后和远程桌面用同一条编码管线（优先硬件编码，否则软件编码；码率自适应；
  丢帧后自动请求关键帧）。只保留最新画面，所以网络慢时延迟不会累积。
- 摄像头由 Agent 以登录用户的身份打开（和文件、终端一样），从不以 SYSTEM 打开；只有登录界面 / UAC 可用时
  拒绝。打开和关闭写入 Agent 日志（`agent-user-*.log`）。如果摄像头被别的程序占用、被拔掉，或 Windows 的
  "设置 > 隐私和安全性 > 摄像头"不允许桌面应用使用，控制端会看到原因。

> 以上以 Windows 为准。macOS 用 AVFoundation 走同一条管线；Linux 走 portal 的摄像头节点 + PipeWire，
> 首次使用需要按“支持矩阵”一节的说明在被控端显式允许摄像头权限。

## 7. 无人值守模式

- **固定密码**：被控端界面支持设置无人值守专用的长效固定密码（至少 8 位字符）。设置后用平台自己的密钥库
  持久化存储（Windows 是 DPAPI，macOS 是 Keychain，Linux 是 0600 文件），机器或服务重启后依然有效。
  控制端输入设备代码和固定密码即可随时接入，无需被控端现场人员配合。随时可在被控端界面的
  "高级设置 → 安全"中修改或删除（"删除"会清掉已保存的密码，之后只能用临时密码连接，直到重新设置）。
  **下限定在 8 位只是下限而不是建议**——口令是这套设计里最薄的一环，能多长就多长（原因见
  [系统设计](../design/README.md) 的“安全边界”一节里关于 PAKE 的说明）。
- **防休眠保护（Keep-Awake）**：被控端在有活跃的远程连接期间，会自动阻止计算机进入睡眠模式
  （各平台用的机制见“支持矩阵”）；所有连接断开后自动恢复默认电源策略，保证远程运维或大文件传输不被闲置睡眠打断。

> **Linux 上固定密码并不能让控制变成无人值守**：portal 不允许远程桌面会话持久化，控制权限每次连接都要有
> 人在机器前点一次同意（见“授权的差别”一节）。

## 8. 会话遥测（默认关闭）

客户端默认**不上报会话质量**（会话结束的例外见本节末尾）。运维部署想要在监控台上看到会话质量，需要显式打开：

```json
{ "Telemetry": { "Enabled": true, "IntervalSeconds": 30 } }
```

这一段在客户端的 `appsettings.json`（`src/Hosts/RemoteDesktop.Client/`）和被控端服务的 `appsettings.json`
（`src/Hosts/RemoteDesktop.HostService/`）里各有一份，默认 `Enabled` 为 `false`、`IntervalSeconds` 为 30；
间隔会被夹在 5 到 3600 秒之间。

打开后，会话开始约 5 秒后先报一次（让第一个往返延迟有机会测出来），之后按配置的间隔（默认 30 秒）通过已有的
信令连接（WebSocket）发一条心跳，内容只有这些字段：

| 字段 | 含义 |
|---|---|
| `sessionId` | 这次会话的随机 id，两端一致；不是设备代码，也不指向某一台机器 |
| `relaySessionId` | 服务端为这次会话签发的 id；直连时也有，让监控台把质量并回同一条记录（未配置中继时为空） |
| `role` / `mode` | 这一端是控制端还是被控端；控制还是观看 |
| `transport` | 直连（P2P）还是中继 |
| `rttMillis` | 控制端测得的往返延迟（就是界面上显示的那个数） |
| `platform` / `version` | 被控端的操作系统与产品版本；控制端不上报平台 |

**没有设备名、没有 IP、没有窗口标题、没有按键、没有文件名。** 心跳只回答"这条链路有多快、跑在什么系统上"，
不回答"谁在用什么"。

- 关掉之后不会有任何**质量**上报，也不会启动定时器——不是"上报后丢弃"。
- 心跳失败不影响会话：发送只是入队，队列满了就丢最旧的一条，断线期间整队清空。
- 被控端也要打开才会出现在「被控端平台」面板里；只开控制端时该面板保持为空，并提示"还没有心跳"。
- **会话结束是例外，始终上报**：无论这个开关是否打开，会话正常结束时两端都会通过信令上报一次
  `session.ended`，内容只有会话 id、中继会话 id（`relaySessionId`，未配置中继时为空）、这一端的角色和结束原因（`closed`）。没有它，直连（P2P）会话在监控台里
  永远不会结束。它不是周期性的，也不含 RTT、平台或版本。

## 1. 评审范围与方法

范围：`RemoteDesktop.Client` 的 `Views/`、`Styles/`、`Controls/`、`ViewModels/` 中用户可见的部分；
`Assets/icon-*.png`、`icon.ico`、`icon.svg`；macOS 的 `AppIcon.icns` 生成与两个 bundle 的 `Info.plist`；
Windows `.ico` 与 Linux `.desktop`/hicolor 的图标安装。

方法：**实机截图 + 代码核对**。在 macOS 26 上用最终签名 bundle 跑了主页、设备列表、高级设置三个标签页、
远程控制、文件传输、终端、摄像头与三个控制器的被控端横幅；随后用逐应用
`NSRequiresAquaSystemAppearance` 在系统保持深色的情况下补看同一组窗口的亮色外观。图标同时核对了源文件、
各尺寸渲染、`.icns` 内部槽位、`.ico` 目录项与 Dock 实际渲染。对比基准为 Apple 的 macOS 图标栅格
（1024 画布、824 主体）与系统自带应用在 Dock 中的观感。

**没有做的**：VoiceOver/放大字体走查、Windows/Linux 的并排视觉比对（见 §5）。

## 2. 确认无问题的部分

1. **视图零平台分支**：三层窗口与子视图仍是单份 XAML；平台差异只来自能力与托管模型，与上一轮评审一致。
2. **主题令牌单一来源**：颜色、间距、圆角、字号都在 `Tokens.axaml`；`RequestedThemeVariant="Default"`
   跟随系统。深色与亮色下正文、次级、三级文字与警告色实测清晰（亮色明细见 R8）。
3. **状态与操作反馈**：连接/断开、录制开始/保存、摄像头授权失败、文件传输完成、终端退出都有明确文案；
   录制保存路径过长时的截断与 ToolTip 已在 `6b91e2f` 修正。
4. **设备列表**：长别名下设备代码完整显示；在线/离线/未知三态有文字与圆点双重表达。
5. **图标资源覆盖**：`AppIcon.icns` 含 16–512@2x 全部 10 个槽位；`icon.ico` 含 16/24/32/48/64/128/256
   共 7 档、32bpp；Linux 只安装 16–512 的标准 hicolor 尺寸；窗口图标与可执行文件图标引用的是同一套资产。
6. **16/24px 简化图形**：去掉支架、放大显示器与指针，在 16px 下仍可辨认为"屏幕 + 指针"，没有糊成一团。

## 3. 评审发现

### R1（P1，已修复）被控端横幅：第三个控制器的操作按钮在视口外

- 位置：`MainWindow.axaml` 的会话横幅；`ScrollViewer MaxHeight="150"`。
- 现象：每个会话把说明、摄像头警告、操作按钮竖排，单项约 100pt。三个控制器时第三项的
  “仅观看/断开”落在 150pt 视口下方，用户必须发现横幅本身可以滚动才能断开它。
- 影响：这是被控端**收回控制权**的入口；按钮不可见会把安全操作变成一次隐藏的滚动发现。
- 修复：说明与按钮改为同一行（`Grid ColumnDefinitions="*,Auto"`），摄像头警告只在适用时多占一行。
  三个控制器的实机截图确认三项的“仅观看/断开”全部可见，`MaxHeight` 不变。

### R2（P1，已修复）`Remote Desktop Host.app` 没有产品图标

- 位置：`build/installer/macos/host/make-app.sh`、`host/Info.plist`。
- 现象：host bundle 的 `Contents/Resources/` 为空，`Info.plist` 没有 `CFBundleIconFile`。虽然
  `LSUIElement` 让它运行时没有 Dock 图标，但 Finder、`/Applications` 与安装包界面仍会显示它——那里是
  通用应用图标。
- 修复：`make-app.sh` 用客户端的 `make-icns.sh` 从同一套 `Assets/icon-*.png` 生成
  `AppIcon.icns`，`Info.plist` 增加 `CFBundleIconFile=AppIcon`；图标在签名前就位，`codesign --verify`
  通过。产品只有一个图标来源，不会出现 host 与 client 两套图。

### R3（P2，待设计决定）macOS 图标主体偏大，Dock 中比系统图标大约 10%

- 现状：`icon.svg` 的蓝色圆角方块是 228×228（256 画布），边距 14（5.5%），圆角 56（主体的 24.6%）。
- 基准：Apple 的 macOS 应用图标栅格是 1024 画布、824 主体（80.5%），即 256 画布下主体 206、边距 25。
- 实测：与 Dock 中的“活动监视器”等系统图标并排，本应用图标明显更高/更宽；Dock 会把图标缩放到槽位，
  所以主体越满，观感越大。
- 建议：**只改主体比例，不改设计语言**——把整幅图形按约 0.904 缩放并居中（主体 206/256、圆角约 50.6），
  16/24 的简化版同样处理，然后重新生成所有 PNG、`.icns` 与 `.ico`。这会让三平台图标同时变小一圈，
  但不改变蓝底、显示器、指针的识别特征。
- 未直接修改的原因：这是跨平台视觉决策（Windows 图标通常更满），需要确认后再动全部尺寸。

### R4（P3，已修复）Dock 悬停提示是 “RemoteDesktop”，与品牌名不一致

- 现象：Dock 悬停显示 `RemoteDesktop`（无空格），菜单栏是 `Remote Desktop`，窗口标题是“远程桌面”。
- 成因：实测确认这个提示取自 `.app` 的文件名（`RemoteDesktop.app`），不是 `CFBundleName` /
  `CFBundleDisplayName`——两者早已是 “Remote Desktop”。把 bundle 复制成 `Remote Desktop.app` 后提示立即
  变为 “Remote Desktop”；仅重新注册 LaunchServices 并重启 Dock 不能改变旧文件名的提示。
- 修复：客户端 bundle 改名为 `Remote Desktop.app`，与 host bundle（`Remote Desktop Host.app`）一致；
  主窗口标题同时由“远程桌面”改为 “Remote Desktop”。打包脚本、CI 校验路径与文档已同步。
- 升级注意：`.pkg` 不会删除旧名字的 bundle，从旧版升级需手动删除 `/Applications/RemoteDesktop.app`；
  若开过登录项，需在新 bundle 中重新开启。

### R5（P3，观察）版本号显示为四段，bundle 是三段

- 侧栏与“数据与诊断”显示 `0.3.0.0`（程序集版本），`Info.plist` 是 `0.3.0`。
- 建议：统一成三段，或在两处都明确是“程序集版本”；当前不影响使用。

### R6（P3，观察）固定密码的“关闭”按钮语义不够明确

- 界面：`已开启（长效密码） [修改] [关闭]`。这里的“关闭”实际是**删除已保存的固定密码**，
  与“修改”并排时容易被读成“关闭编辑框”。
- 建议：改为“清除固定密码”或“停用”。文档用的是“开启、修改或关闭”，当前文案不算错误，只是歧义。

### R7（P3，已修复）终端窗口的 “Shell” 标签是英文

- `TerminalWindow.axaml` 的下拉框标签为 `Shell`。在中文界面里属于技术术语，可接受；若追求全中文，
  可改为“终端类型”或“Shell 类型”。
- 修复：标签改为“终端类型”，`AutomationProperties.Name` 同步更新。

### R8（P3，已补做）亮色外观实机核验

- 做法：系统保持深色，用 `defaults write com.remotedesktop.client NSRequiresAquaSystemAppearance -bool YES`
  让本应用单独走 Aqua；逐屏截取主页、设备列表、三项高级设置、远程桌面、文件传输、终端、摄像头，
  以及被控端的两控制器警告横幅（含“正在使用本机摄像头”）。核验后已删除该默认值。
- 结果：主/次/三级文字、卡片、边框、连接按钮、警告横幅（浅琥珀底 + 深棕字）与工具栏均清晰；
  摄像头画面、状态栏与录制控件在亮色窗口下无压盖。窗口标题在亮色下同样显示 “Remote Desktop”。
- 唯一问题见 R9。

### R9（P3，观察）亮色下隐藏文件的元数据对比度不足

- 位置：`FilePaneView.axaml` 的行模板对整个 `Grid` 应用 `Opacity="{Binding RowOpacity}"`，
  `FilePaneViewModel.RowOpacity` 对隐藏文件返回 0.5。
- 现象：亮色下隐藏文件的大小/日期使用 `caption`（`#4B5563`），再乘 50% 透明度后对比度约 2.3:1，
  低于正文的 4.5:1；深色下同样被削弱，但不如亮色明显。
- 影响：隐藏文件仍然可以选择、重命名与删除，信息本身不丢失；纯可读性问题。
- 建议：把 0.5 提高到约 0.8（或只淡化图标/文件名、保留元数据的不透明度），但会削弱“隐藏”的视觉提示，
  属于设计取舍，本轮未改。

### R10（P3，已修复）录制按钮比其他工具栏按钮高

- 现象：远程桌面与摄像头的录制/停止按钮比相邻按钮高；远程桌面工具栏里只有它明显凸出。
- 成因：按钮文案带 emoji 前缀 `⏺`/`⏹`（U+23FA / U+23F9，Emoji_Presentation），Apple Color Emoji 的
  行高大于正文；Avalonia 按内容测量按钮高度，于是这一个按钮单独长高。
- 修复：改用文本呈现的 `●`/`■`。实机量得远程桌面工具栏六个按钮（静音、录制、文件、终端、摄像头、断开）
  均为 64px（32pt），摄像头工具栏的“开始/停止/录制摄像头”同为 64px；viewmodel 注释说明保留原因。

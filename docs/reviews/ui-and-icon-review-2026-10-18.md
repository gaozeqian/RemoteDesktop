### 1. 评审范围与方法

范围：`RemoteDesktop.Client` 的 `Views/`、`Styles/`、`Controls/`、`ViewModels/` 中用户可见的部分；
`Assets/icon-*.png`、`icon.ico`、`icon.svg`；macOS 的 `AppIcon.icns` 生成与两个 bundle 的 `Info.plist`；
Windows `.ico` 与 Linux `.desktop`/hicolor 的图标安装。

方法：**实机截图 + 代码核对**。在 macOS 26 上用最终签名 bundle 跑了主页、设备列表、高级设置三个标签页、
远程控制、文件传输、终端、摄像头与三个控制器的被控端横幅；随后用逐应用
`NSRequiresAquaSystemAppearance` 在系统保持深色的情况下补看同一组窗口的亮色外观。图标同时核对了源文件、
各尺寸渲染、`.icns` 内部槽位、`.ico` 目录项与 Dock 实际渲染。对比基准为 Apple 的 macOS 图标栅格
（1024 画布、824 主体）与系统自带应用在 Dock 中的观感。

**没有做的**：VoiceOver/放大字体走查、Windows/Linux 的并排视觉比对（见 §5）。

### 3. 评审发现

#### R1（P1，已修复）被控端横幅：第三个控制器的操作按钮在视口外

- 位置：`MainWindow.axaml` 的会话横幅；`ScrollViewer MaxHeight="150"`。
- 现象：每个会话把说明、摄像头警告、操作按钮竖排，单项约 100pt。三个控制器时第三项的
  “仅观看/断开”落在 150pt 视口下方，用户必须发现横幅本身可以滚动才能断开它。
- 影响：这是被控端**收回控制权**的入口；按钮不可见会把安全操作变成一次隐藏的滚动发现。
- 修复：说明与按钮改为同一行（`Grid ColumnDefinitions="*,Auto"`），摄像头警告只在适用时多占一行。
  三个控制器的实机截图确认三项的“仅观看/断开”全部可见，`MaxHeight` 不变。

#### R2（P1，已修复）`Remote Desktop Host.app` 没有产品图标

- 位置：`build/installer/macos/host/make-app.sh`、`host/Info.plist`。
- 现象：host bundle 的 `Contents/Resources/` 为空，`Info.plist` 没有 `CFBundleIconFile`。虽然
  `LSUIElement` 让它运行时没有 Dock 图标，但 Finder、`/Applications` 与安装包界面仍会显示它——那里是
  通用应用图标。
- 修复：`make-app.sh` 用客户端的 `make-icns.sh` 从同一套 `Assets/icon-*.png` 生成
  `AppIcon.icns`，`Info.plist` 增加 `CFBundleIconFile=AppIcon`；图标在签名前就位，`codesign --verify`
  通过。产品只有一个图标来源，不会出现 host 与 client 两套图。

#### R3（P2，待设计决定）macOS 图标主体偏大，Dock 中比系统图标大约 10%

- 现状：`icon.svg` 的蓝色圆角方块是 228×228（256 画布），边距 14（5.5%），圆角 56（主体的 24.6%）。
- 基准：Apple 的 macOS 应用图标栅格是 1024 画布、824 主体（80.5%），即 256 画布下主体 206、边距 25。
- 实测：与 Dock 中的“活动监视器”等系统图标并排，本应用图标明显更高/更宽；Dock 会把图标缩放到槽位，
  所以主体越满，观感越大。
- 建议：**只改主体比例，不改设计语言**——把整幅图形按约 0.904 缩放并居中（主体 206/256、圆角约 50.6），
  16/24 的简化版同样处理，然后重新生成所有 PNG、`.icns` 与 `.ico`。这会让三平台图标同时变小一圈，
  但不改变蓝底、显示器、指针的识别特征。
- 未直接修改的原因：这是跨平台视觉决策（Windows 图标通常更满），需要确认后再动全部尺寸。

#### R4（P3，已修复）Dock 悬停提示是 “RemoteDesktop”，与品牌名不一致

- 现象：Dock 悬停显示 `RemoteDesktop`（无空格），菜单栏是 `Remote Desktop`，窗口标题是“远程桌面”。
- 成因：实测确认这个提示取自 `.app` 的文件名（`RemoteDesktop.app`），不是 `CFBundleName` /
  `CFBundleDisplayName`——两者早已是 “Remote Desktop”。把 bundle 复制成 `Remote Desktop.app` 后提示立即
  变为 “Remote Desktop”；仅重新注册 LaunchServices 并重启 Dock 不能改变旧文件名的提示。
- 修复：客户端 bundle 改名为 `Remote Desktop.app`，与 host bundle（`Remote Desktop Host.app`）一致；
  主窗口标题同时由“远程桌面”改为 “Remote Desktop”。打包脚本、CI 校验路径与文档已同步。
- 升级注意：`.pkg` 不会删除旧名字的 bundle，从旧版升级需手动删除 `/Applications/RemoteDesktop.app`；
  若开过登录项，需在新 bundle 中重新开启。

#### R5（P3，观察）版本号显示为四段，bundle 是三段

- 侧栏与“数据与诊断”显示 `0.3.0.0`（程序集版本），`Info.plist` 是 `0.3.0`。
- 建议：统一成三段，或在两处都明确是“程序集版本”；当前不影响使用。

#### R6（P3，观察）固定密码的“关闭”按钮语义不够明确

- 界面：`已开启（长效密码） [修改] [关闭]`。这里的“关闭”实际是**删除已保存的固定密码**，
  与“修改”并排时容易被读成“关闭编辑框”。
- 建议：改为“清除固定密码”或“停用”。文档用的是“开启、修改或关闭”，当前文案不算错误，只是歧义。

#### R7（P3，已修复）终端窗口的 “Shell” 标签是英文

- `TerminalWindow.axaml` 的下拉框标签为 `Shell`。在中文界面里属于技术术语，可接受；若追求全中文，
  可改为“终端类型”或“Shell 类型”。
- 修复：标签改为“终端类型”，`AutomationProperties.Name` 同步更新。

#### R8（P3，已补做）亮色外观实机核验

- 做法：系统保持深色，用 `defaults write com.remotedesktop.client NSRequiresAquaSystemAppearance -bool YES`
  让本应用单独走 Aqua；逐屏截取主页、设备列表、三项高级设置、远程桌面、文件传输、终端、摄像头，
  以及被控端的两控制器警告横幅（含“正在使用本机摄像头”）。核验后已删除该默认值。
- 结果：主/次/三级文字、卡片、边框、连接按钮、警告横幅（浅琥珀底 + 深棕字）与工具栏均清晰；
  摄像头画面、状态栏与录制控件在亮色窗口下无压盖。窗口标题在亮色下同样显示 “Remote Desktop”。
- 唯一问题见 R9。

#### R9（P3，观察）亮色下隐藏文件的元数据对比度不足

- 位置：`FilePaneView.axaml` 的行模板对整个 `Grid` 应用 `Opacity="{Binding RowOpacity}"`，
  `FilePaneViewModel.RowOpacity` 对隐藏文件返回 0.5。
- 现象：亮色下隐藏文件的大小/日期使用 `caption`（`#4B5563`），再乘 50% 透明度后对比度约 2.3:1，
  低于正文的 4.5:1；深色下同样被削弱，但不如亮色明显。
- 影响：隐藏文件仍然可以选择、重命名与删除，信息本身不丢失；纯可读性问题。
- 建议：把 0.5 提高到约 0.8（或只淡化图标/文件名、保留元数据的不透明度），但会削弱“隐藏”的视觉提示，
  属于设计取舍，本轮未改。

#### R10（P3，已修复）录制按钮比其他工具栏按钮高

- 现象：远程桌面与摄像头的录制/停止按钮比相邻按钮高；远程桌面工具栏里只有它明显凸出。
- 成因：按钮文案带 emoji 前缀 `⏺`/`⏹`（U+23FA / U+23F9，Emoji_Presentation），Apple Color Emoji 的
  行高大于正文；Avalonia 按内容测量按钮高度，于是这一个按钮单独长高。
- 修复：改用文本呈现的 `●`/`■`。实机量得远程桌面工具栏六个按钮（静音、录制、文件、终端、摄像头、断开）
  均为 64px（32pt），摄像头工具栏的“开始/停止/录制摄像头”同为 64px；viewmodel 注释说明保留原因。

1. **视图仍是单份共享**：Windows 没有独立的 XAML 分支；主题通过 Avalonia FluentTheme 与系统
   `AppsUseLightTheme` 接入，与 macOS 评审的结论一致。
2. **主窗口信息架构**：三个标签页内容完整，连接方式、最近连接、设备详情、固定密码、托管方式、
   数据目录的标签与值对齐；按钮禁用态（未选设备、未连接、非服务托管）符合预期。
3. **主要操作窗口**：远程桌面的工具栏与状态栏、文件传输的双栏与冲突策略、终端的标签页与新标签、
   摄像头的设备/分辨率/录制控件均无压盖；被控端 1/2/3 会话横幅的“仅观看/断开”全部可见。
4. **深浅色跟随**：系统主题切换后窗口即时跟随；正文、次级文字、卡片、边框、警告色与焦点框都清晰，
   没有出现深色下白底控件或亮色下不可读的标签。
5. **图标资产**：`icon.ico` 含 16/24/32/48/64/128/256 共 7 档、32bpp；窗口图标与可执行文件图标来自
   同一套 PNG；16/24px 简化图形在深色与浅色背景上都能辨认为“屏幕 + 指针”。
6. **安装包图标接线**：client 与 server 包的 `Icon` 表、`ARPPRODUCTICON` 指向同一 `icon.ico`，
   client 的开始菜单快捷方式显式引用 `AppIcon`。

### 9. 评审发现

#### W1（P1，已修复）独立模式下“本机控制端代码”的说明与事实相反

- 位置：`MainWindowViewModel` 的 `ClientCodeNote`；`ClientEnvironment`/`ClientHost` 的托管模式传递。
- 现象：以独立模式（未安装后台服务）运行时，被控端就在本进程内，本机控制端代码与主页显示的是同一个；
  界面却沿用“两者不一样、主页显示的是后台服务代码”的说明。即使安装了服务，首帧也先显示这句默认文案，
  要等第一次主机状态轮询回来才纠正。
- 影响：用户被问起“谁在连我”时会拿错代码；这是排障与安全确认时的直接误导。
- 修复：`ClientEnvironment` 增加 `ControlledEndInThisProcess`，`ClientHost` 按是否使用服务注入；
  `MainWindowViewModel` 在构造时即按托管模式生成说明，主机状态返回后再按 `status.IsService` 刷新。
  `MainWindowPlatformNoteTests` 覆盖两种托管模式下的完整文案。

#### W2（P1，已修复）独立模式下“被控端信令服务器”是可编辑的死路

- 位置：`MainWindow.axaml` 的服务器与托管页；`MainWindowViewModel.CanEditHostServerAddress`。
- 现象：独立模式仍显示“修改”按钮与地址编辑框，说明承诺“请求管理员权限 (UAC)，完成后自动重启服务”，
  但保存实际失败并提示“找不到后台服务程序，可能客户端未作为服务安装”（评审截图存有修复前状态）。
  用户没有任何能走通的下一步。
- 影响：这是把客户端指向另一台服务器的入口；在独立模式下它既不该出现，也不该给出做不到的承诺。
- 修复：只有被控端确实以后台服务托管且已知地址时才显示编辑入口
  （`CanEditHostServerAddress = status.IsService && !string.IsNullOrEmpty(status.RendezvousUri)`）；
  独立模式下该说明改为“关闭客户端，改启动参数（`--Transport:RendezvousUri`）或 `appsettings.json` 后再启动”。
- 验证：同一窗口在修复后只剩客户端信令服务器一行与上述说明，没有“修改/保存”按钮。

#### W3（P2，已修复）最近连接超过约 5 条时，底部的在线状态说明被压到状态栏下

- 位置：`MainWindow.axaml` 的设备列表左侧卡片。
- 现象：卡片用纵向 StackPanel 依次放标题、列表与说明；列表随最近连接增长，说明被一路向下推，
  在 5 条记录时已落到窗口可视区之外，且卡片本身不能滚动。
- 修复：改为 `Auto,*,Auto` 的 Grid：标题与刷新固定在顶部，列表占据中间可滚动行，两条说明固定在底部。
- 验证：5 条记录时说明完整可见，列表出现自己的滚动条，窗口尺寸不变。

#### W4（P2，已修复）数据目录路径过长时被裁切，复制按钮被挤出视野

- 位置：`MainWindow.axaml` 的数据与诊断页。
- 现象：路径文本放在横向 StackPanel 中，`SelectableTextBlock` 不换行；长路径把“复制”按钮推到卡片外，
  路径与按钮同时被裁切。
- 修复：改为 `*,Auto` 的 Grid，路径允许换行、按钮固定在最右列。
- 验证：`C:\Users\…\artifacts\e2e-windows\rd1` 完整换行显示，复制按钮可见可点。

#### W5（P2，已修复）下拉框的无障碍名称与折叠值

- 位置：`FilePaneView.axaml`、`CameraWindow.axaml`、`FileManagerWindow.axaml`、`MainWindow.axaml`；
  `CameraChoice`/`CameraModeChoice`/`ConflictChoice`/`PlaceInfo`。
- 现象：UI Automation 读到的折叠值是整条记录，例如
  `CameraChoice { Camera = CameraInfo { … } }`、`ConflictChoice { Label = …, Policy = … }`、
  `PlaceInfo { Name = …, Path = … }`；同时“快速访问”“摄像头”“分辨率”“文件已存在时”“连接方式”
  与左侧“主导航”没有 `AutomationProperties.Name`，读屏只能报“组合框”或“列表”。
- 影响：4 个下拉框的值无法被读屏理解，6 处控件缺少上下文；键盘用户仍可操作，但屏幕阅读器用户不能。
- 修复：四个记录类型重写 `ToString()` 返回界面上看到的文字；六处控件补名称。
  下拉框展开后仍使用原有 DataTemplate，视觉不变。
- 验证：UIA 树中折叠值分别为摄像头名、`1280×720 · 30 fps`、`覆盖/跳过/重命名` 等标签，
  控件名称在上述六处可读。

#### W6（P1，已修复）MSI 安装包没有产品图标

- 位置：`build/installer/windows/client/Package.wxs`、`build/installer/windows/server/Package.wxs`、
  `build/installer/windows/client/Components.wxs`。
- 现象：两个包都没有 `Icon` 表项与 `ARPPRODUCTICON`，client 的开始菜单快捷方式也没有 `Icon` 属性。
  结果是“设置 > 应用”里显示通用图标；快捷方式只能回落到目标 exe 的图标，包本身没有声明用哪一个。
- 修复：两个包各加 `Icon Id="AppIcon"`（指向客户端 `Assets/icon.ico`）与
  `Property Id="ARPPRODUCTICON"`；client 的开始菜单快捷方式加 `Icon="AppIcon"`。
- 验证：用最小 WiX 工程实际链接出一个 MSI，`InstallerPackageTests.The_package_carries_the_product_icon`
  通过 Windows Installer API 查询确认 `Icon` 表含 `AppIcon`、`ARPPRODUCTICON=AppIcon`、
  `Shortcut.Icon_=AppIcon`。测试在没有 MSI 时跳过，构建机产出安装包后自动生效。

#### W7（P3，观察）`.ico` 没有 20/40px 槽位

- 现状：7 档为 16/24/32/48/64/128/256；Windows 在 125%/150% 缩放下常取 20/24/32/40px。
- 实测：缺少的 20/40px 由 shell 从相邻档位缩放；逐尺寸渲染图与资源管理器中的 16–256 观感清晰，
  16/24px 简化图形没有粘连。
- 建议：只有在 125%/150% 实机上看到模糊时再补 20/40px；本轮不改，避免为一个未复现的问题重导全部资产。

#### W8（P3，观察）浅色下隐藏文件行的元数据对比度不足

- 与第一轮 R9 同一处：`FilePaneView.axaml` 对整行应用 `Opacity="{Binding RowOpacity}"`，隐藏文件为 0.5；
  亮色下 `caption` 灰再乘 50% 后低于 4.5:1。Windows 实机复现，深色下同样被削弱但不刺眼。
- 未改：提高不透明度会削弱“隐藏”提示，属于设计取舍，与 R9 一并待决定。

#### W9（P3，观察）版本号显示为四段

- 状态栏与“数据与诊断”显示 `0.3.0.0`（程序集版本），`Info.plist`/包版本是 `0.3.0`；
  与第一轮 R5 同一问题，Windows 侧没有新增格式差异。

#### W10（P3，观察）浅色主题下终端保持深色

- `TerminalTabView.axaml` 明确让终端在两种主题下都用自己的深色调色板；窗口边框与标签栏跟随浅色。
- 实测文字对比度正常，窗口一眼可辨为终端；这是有注释说明的设计选择，不作修改。

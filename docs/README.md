# Remote Desktop 文档中心

技术文档的入口。**四份正文 + 一份规范**，一个目录一份完整文档，按读者分：

| 我要…… | 打开 |
|---|---|
| 用这个软件 / 搞清它支持什么 | [`usage/`](usage/README.md) |
| 改代码 | [`design/`](design/README.md) |
| 部署与运维 | [`ops/`](ops/README.md) |
| 把产品搬到新平台 | [`ports/`](ports/README.md) |
| 写或改文档 | [`STYLE.md`](STYLE.md) |

这份清单是**唯一的一份**。不要在别处重列文档清单——手工维护的第二份索引必然与这份分叉，这个仓库已经发生过
一次（根 README 里那份漏掉了四份文档）。索引完整性、命名、链接是否可解析都由 `DocumentationTests` 断言，
漏加新文档会让构建变红。

## 使用（`usage/`）

**给用这个软件的人。** 三平台能力矩阵、被控端形态、各平台**不支持**的东西及原因、自检开关；连接、
远程桌面窗口、文件传输、远程终端、远程摄像头、无人值守模式各自怎么用、有什么边界。

## 设计（`design/`）

**给要改代码的人。** 五块内容：§1 分层与模块职责（决定你把代码放哪）、§2 通信协议（跨端契约，
改动要两端一起动）、§3 安全边界（保护了什么、**还没有保护什么**）、§4 运维监控台（构成、数据来源、
认证与告警）、§5 客户端本机存储（最近设备列表怎么存）。服务端怎么存设备代码（端口、方言、
加一种数据库要动哪几处）在 §1 的"服务端持久化"一节。

## 运维（`ops/`）

**给要部署和运维的人。** 先决条件、架服务器（Linux `.deb` / Windows MSI / macOS `.pkg`，含 Docker 与 TLS）、
发版、客户端与被控端的安装与卸载、打包脚本的内部细节、客户端本机存了什么、故障速查，以及运维监控台的部署
（§二 10；其设计见[系统设计](design/README.md) §4）、一份上线前逐条照做的真机验收清单（§十二）。

## 平台移植（`ports/`）

**给要把产品搬到某个平台的人。** 两个移植（macOS / Linux）已全部完成，这份文档记的是**结论**：定下了什么、
每个平台有哪些绕不过去的硬约束、哪些地方**还没验证过**。实测过程（命令与输出）不在文档里——
需要复现某条结论时去 git 历史里找。

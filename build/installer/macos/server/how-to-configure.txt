Remote Desktop 服务器（macOS）—— 装好之后怎么改配置
==================================================

这个目录里放着四个服务器程序（Rendezvous/ 信令、Relay/ 中继、Ops/ 运维监控台、Gateway/ 运维台
HTTPS 反向代理）、它们的配置（各自目录下的 appsettings.json），以及这个说明。

安装时，安装器里有一页"服务器配置"，可以选择数据库（SQLite / PostgreSQL）与 TLS（不用 / 生成自签名 /
使用已有证书）。**升级时同一页默认勾选"保留现有设置"**，不会把运维改过的值覆盖掉。
无人值守安装（sudo installer、MDM）可以把同样的答案写在
/Library/Application Support/RemoteDesktop/install-answers.plist（root:wheel，0600），
键名见安装器页面；没有这个文件时，升级只更新程序、保留配置。

它们由 launchd 以系统守护进程（LaunchDaemon）的方式运行，开机自启、崩溃自动重启：
    /Library/LaunchDaemons/com.remotedesktop.rendezvous.plist
    /Library/LaunchDaemons/com.remotedesktop.relay.plist
    /Library/LaunchDaemons/com.remotedesktop.ops.plist
    /Library/LaunchDaemons/com.remotedesktop.gateway.plist


一、改配置的推荐做法：用同目录下的脚本
--------------------------------------

在**管理员**终端里（sudo）：

    cd /usr/local/remotedesktop-server
    sudo ./configure-server.sh --database sqlite
    sudo ./configure-server.sh --postgres 'Host=db;Port=5432;Database=remotedesktop;Username=rd;Password=...'

它会做两件事：把设置写进 appsettings.json，然后重启四个守护进程让它们生效（监控台也重启，
因为数据库 provider 是两边共享的）。只给想改的项就行，没给的保持不动。可用的项
（`sudo ./configure-server.sh --help` 也列了）：

    --database            设备代码存在哪：auto / none / postgres / sqlite。
                          auto = 本机已有 PostgreSQL 就继续用它，否则建一个 SQLite 库
    --database-path       SQLite 文件；不给就用 /usr/local/remotedesktop-server/var/rendezvous.db
    --postgres            PostgreSQL 连接串；传 '' 表示不再用 PostgreSQL
    --relay-endpoint      让客户端去哪里找中继，IP:端口
    --urls                信令自己绑定的地址，如 https://0.0.0.0:5080
    --relay-key           中继票据的签名密钥（中继在另一台机器上时两边必须一致）
    --tls-certificate/--tls-password   用已有的证书文件启用 https；--tls-certificate generate 则生成自签名证书
    --ops-listen          监控台的监听地址（默认 http://127.0.0.1:5090）
    --ops-database-path   监控台的 SQLite 文件（默认 .../var/ops.db）
    --gateway-listen      运维台公网 HTTPS 地址（默认 https://0.0.0.0:5443）
    --gateway-hostname    生成证书里额外包含的 IP/DNS（逗号分隔；本机 IPv4 会自动包含）
    --no-restart          写完不重启（下次重启才生效）

执行过什么，都追加记录在同目录的 server-setup.log 里。


二、两个必须知道的默认值
------------------------

1. 设备代码默认存在本机的一个 SQLite 文件里（var/rendezvous.db），重启后不变。
   只有明确用 --database none 才回到内存模式 —— 那种情况下信令服务一重启，
   所有设备代码都会变，被设成无人值守的机器会因此失联。
   **这个文件要备份**：删掉它等于所有设备码重发。它只支持本地磁盘，放在网络共享上会损坏。

2. 不配证书时信令走明文 http —— 设备代码、谁在连谁、以及中继票据都在明文里。
   macOS 上要开 TLS，用仓库里的 build/signing/New-ServerCertificate.ps1 生成一张证书
   （纯 .NET，macOS 上同样能跑），然后把 .pfx 交给：

       sudo ./configure-server.sh --urls https://0.0.0.0:5080 \
            --tls-certificate /path/to/rd.lan.pfx --tls-password <口令>

   客户端必须信任这张证书（否则会拒绝连接）。在客户端/被控端的安装器里选择这张证书的公钥文件即可：
   安装器会把它复制到 /Library/Application Support/RemoteDesktop/certificates/，客户端/被控端**只信任这一张
   证书**（证书固定），不会修改系统钥匙串或系统信任设置。
   注意**证书里的名字或地址要和客户端填的地址一致**。

   用 `--tls-certificate generate` 生成时，公开部分在
   /usr/local/remotedesktop-server/tls/signaling.crt，安装器还会复制一份到
   /usr/local/share/doc/remotedesktop-server/signaling.crt，方便拷给客户端机器。


三、也可以直接改 appsettings.json
--------------------------------

两个服务器的配置分别在 Rendezvous/appsettings.json 和 Relay/appsettings.json，
格式普通，改完重启对应守护进程即可：

    sudo launchctl kickstart -k system/com.remotedesktop.rendezvous
    sudo launchctl kickstart -k system/com.remotedesktop.relay

appsettings.json 在升级时**不会被覆盖**，所以手改的值会保留。但注意它就在本目录下，
**本机任何用户都能读**——带口令的数据库连接串放在这里，等于本机所有用户都能看到。


四、日志与健康检查
------------------

    logs/rendezvous.log、logs/relay.log      两个网络服务器的标准输出
    logs/ops.log                             运维监控台的标准输出
    logs/gateway.log                         运维台 HTTPS 反向代理的标准输出
    curl http://127.0.0.1:5080/health        信令是否活着（返回 Healthy）
    curl http://127.0.0.1:5090/health        监控台是否活着（仅本机）


五、卸载
--------

    cd /usr/local/remotedesktop-server
    sudo ./uninstall-server.sh

它会停掉四个守护进程、删掉 plist、这个目录、/usr/local/share/doc/remotedesktop-server 以及安装回执。
加 --keep-settings 只删程序、留下配置、日志和导出的证书。

注意：中继密钥在配置里。如果中继装在另一台机器上，那台机器用的是**这台机器**的密钥；
在这里删掉它，就等于下次安装时那台机器要重新配置一遍。


六、运维监控台（Ops）的第一个账号
------------------------------------

监控台没有默认口令，也没有网页初始化入口。第一个管理员要在终端里建：

    sudo ./Ops/RemoteDesktop.Server.Ops --create-admin admin

它会交互式地问口令，然后打印一个 TOTP 密钥和 otpauth:// 链接，用验证器扫码即可。**密钥只显示这一次**，
丢了只能再建一个账号。之后每次登录都要口令 + TOTP。

监控台本身仍只监听 127.0.0.1:5090。安装包同时安装 Gateway，默认监听
https://0.0.0.0:5443 并转发到该回环地址，因此其他机器可以直接访问：

    https://<服务器IP>:5443

Gateway 使用自动生成、包含本机 IPv4 IP SAN 的自签名证书。公钥导出为
/usr/local/share/doc/remotedesktop-server/ops-gateway.crt。每台运维电脑必须一次性信任它，
不能靠忽略浏览器证书警告代替。先复制到运维电脑并核对服务器上的 SHA-256 指纹：

    scp <管理员>@<服务器IP>:/usr/local/share/doc/remotedesktop-server/ops-gateway.crt .
    openssl x509 -in ops-gateway.crt -noout -fingerprint -sha256

在每台 macOS 运维电脑上执行：

    sudo security add-trusted-cert -d -r trustRoot \
        -k /Library/Keychains/System.keychain ops-gateway.crt

也可以在“钥匙串访问”中导入证书，打开证书详情的“信任”，把“使用此证书时”设置为
“始终信任”。Safari 和 Chrome 会使用系统钥匙串；Firefox 使用独立信任库，需要在
“设置 -> 隐私与安全 -> 证书 -> 查看证书 -> 证书颁发机构”中导入并信任。

导入后关闭并重新打开浏览器，访问 https://<服务器IP>:5443，应显示正常的锁标识且没有
证书警告。服务器 IP 改变或证书重新生成后，需要重新分发并信任新证书。macOS 的安装包
不能替其他电脑修改系统钥匙串。

安装器会把本机的信令（127.0.0.1:5080 或 https://<主机名>:5080）和中继（127.0.0.1:5083）
登记为监控台的本地节点，并给信令打开 /metrics；所以新装的节点页从第一次抓取起就有数据。
如果这一步被跳过了（例如数据库当时连不上），在监控台的"节点管理"页手工添加同样两个地址即可。

它的数据库在 var/ops.db（与设备码的 var/rendezvous.db 同一个 0700 目录）。删掉它等于丢掉监控历史、
告警和审计记录，但**不影响**远程桌面连接本身。

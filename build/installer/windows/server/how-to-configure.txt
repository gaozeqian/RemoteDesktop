Remote Desktop 服务器 —— 装好之后怎么改配置
============================================

这个目录里放着四个服务器程序（Rendezvous\ 信令、Relay\ 中继、Ops\ 运维监控台、Gateway\ 运维台 HTTPS
反向代理）。程序的配置默认值就在各自的 appsettings.json 里，**真正生效的设置、数据库、TLS 证书公钥和
server-setup.log 都在** %ProgramData%\Remote Desktop Server\ 下面：

    %ProgramData%\Remote Desktop Server\Rendezvous\appsettings.json
    %ProgramData%\Remote Desktop Server\Relay\appsettings.json
    %ProgramData%\Remote Desktop Server\Ops\appsettings.json
    %ProgramData%\Remote Desktop Server\Gateway\appsettings.json
    %ProgramData%\Remote Desktop Server\server-setup.log
    %ProgramData%\Remote Desktop Server\tls\signaling.cer      （自动生成证书时）

升级/同版本重装不会碰这个目录；安装时给的属性只在**第一次安装**时写入，之后的升级保留现有设置。
这个目录只有 SYSTEM 和 Administrators 能读，因为里面有中继密钥和（如果用 PostgreSQL）数据库口令。


一、改配置的推荐做法：用同目录下的脚本
--------------------------------------

在**管理员**命令提示符或 PowerShell 里：

    cd "C:\Program Files\Remote Desktop Server"
    .\Set-ServerConfiguration.cmd -DatabaseProvider sqlite
    .\Set-ServerConfiguration.cmd -PostgresConnectionString 'Host=db;Port=5432;Database=remotedesktop;Username=rd;Password=...'

`Set-ServerConfiguration.cmd` 只是用 `-ExecutionPolicy Bypass` 启动旁边的 `.ps1`，所以 Windows 11
客户端默认的 Restricted 策略不会挡住它。也可以直接用 PowerShell：

    powershell -ExecutionPolicy Bypass -File .\Set-ServerConfiguration.ps1 ...

它会做三件事：把设置写进 ProgramData 下的配置文件，登记/更新监控台里的本机节点，然后重启四个服务
让它们生效。只给想改的项就行，没给的保持不动。可用的项：

    -DatabaseProvider           设备代码存在哪：auto / none / postgres / sqlite。
                                auto（安装包的默认值）= 本机已有 PostgreSQL 就继续用它，否则建一个 SQLite 库
    -DatabasePath               SQLite 文件路径；不给就用 %ProgramData%\Remote Desktop Server\rendezvous.db
    -PostgresConnectionString   PostgreSQL 连接串；传空字符串表示不再用 PostgreSQL
    -RelayPublicEndpoint        让客户端去哪里找中继，IP:端口
    -RendezvousUrl              信令自己绑定的地址，如 https://0.0.0.0:5080
    -RelaySharedKey             中继票据的签名密钥（中继在另一台机器上时两边必须一致）
    -TlsCertificatePath/-TlsCertificatePassword   用已有的证书文件启用 https
    -TlsGenerate                让本机生成一张自签名证书并启用 https
    -TlsHostName                证书里要包含的 DNS 名/IP（逗号分隔）；只和 -TlsGenerate 一起用
    -OpsListen                  监控台监听地址（默认 http://127.0.0.1:5090，保持回环）
    -OpsDatabasePath            监控台的 SQLite 文件（默认 %ProgramData%\Remote Desktop Server\ops.db）
    -GatewayListen              运维台公网 HTTPS 地址（默认 https://0.0.0.0:5443）
    -GatewayHostName            生成证书里额外包含的 IP/DNS（逗号分隔；本机 IPv4 会自动包含）
    -NoRestart                  写完不重启（下次重启才生效）
    -WhatIf                     只打印将要执行什么，什么都不改（不打印口令）

不知道会做什么就先加 -WhatIf 看一遍。执行过什么都会追加到
%ProgramData%\Remote Desktop Server\server-setup.log。


二、两个必须知道的默认值
------------------------

1. 设备代码默认存在本机的一个 SQLite 文件里
   （%ProgramData%\Remote Desktop Server\rendezvous.db），重启后不变。只有明确用
   -DatabaseProvider none 才回到内存模式 —— 那种情况下信令服务一重启，所有设备代码都会变，
   被设成无人值守的机器会因此失联。
   **这个文件要备份**：删掉它等于所有设备码重发。它只支持本地磁盘，放在网络共享上会损坏。

2. 不配证书时信令走明文 http —— 设备代码、谁在连谁、以及中继票据都在明文里。
   用 -TlsGenerate 一条命令就能切到 https；生成的证书在本机证书存储里，
   公钥导出为 %ProgramData%\Remote Desktop Server\tls\signaling.cer，**客户端必须信任它**
   （否则会拒绝连接）：
   把 signaling.cer 拷到客户端机器，
   Import-Certificate -FilePath signaling.cer -CertStoreLocation Cert:\LocalMachine\Root

   客户端用 DNS 名或公网/NAT 地址访问时，生成证书时要把这些名字写进 -TlsHostName；
   否则客户端即使信任了证书，也会因为名称不匹配而拒绝连接。


三、也可以直接改 appsettings.json
--------------------------------

真正的配置文件在 %ProgramData%\Remote Desktop Server\ 下的 Rendezvous、Relay、Ops 三个子目录里，
格式普通，改完重启对应服务即可。它们在升级时**不会被覆盖**，所以手改的值会保留。
目录只有 SYSTEM 和 Administrators 能读，带口令的数据库连接串不会对本机普通用户可见；
需要让服务读到修改时，请用管理员权限编辑并重启服务。


四、运维监控台（Ops）
--------------------

监控台是第三个服务（服务名 RemoteDesktopOps），默认只监听 127.0.0.1:5090，数据库在
%ProgramData%\Remote Desktop Server\ops.db。安装包同时安装 HTTPS 反向代理 Gateway（服务名
RemoteDesktopGateway），默认监听 https://0.0.0.0:5443 并转发到
http://127.0.0.1:5090；防火墙只为 Gateway 开放 TCP 5443，不开放 5090。

Gateway 使用自动生成的自签名证书，证书包含本机 IPv4 地址作为 IP SAN，所以没有域名也可以访问：

    https://<服务器IP>:5443

公钥导出为 %ProgramData%\Remote Desktop Server\tls\signaling.cer。每台运维电脑必须一次性信任它。
先把公钥复制到运维电脑（或通过其他可信方式传输），并在**管理员 PowerShell** 中执行：

    Import-Certificate -FilePath .\signaling.cer -CertStoreLocation Cert:\LocalMachine\Root

这会写入本机所有用户共用的受信任根，Chrome 和 Edge 会直接使用。执行后关闭并重新打开
浏览器，访问 https://<服务器IP>:5443，地址栏应显示正常的锁标识且没有证书警告。

Firefox 使用自己的信任库，需要在“设置 -> 隐私与安全 -> 证书 -> 查看证书 ->
证书颁发机构”中导入该文件，并勾选“信任由此证书颁发机构来标识网站”。

不要靠忽略浏览器证书警告来访问；服务器 IP 变化后需要重新生成/分发证书。分发前可在
服务器上用 openssl x509 -in 证书文件 -noout -fingerprint -sha256 核对指纹。

安装时会自动把本机的信令/中继登记为两个节点，并打开信令的 /metrics；新装环境不需要手工添加节点。
它没有默认口令，也没有网页初始化入口，第一个管理员要在**管理员** PowerShell 里建：

    & "C:\Program Files\Remote Desktop Server\Ops\RemoteDesktop.Server.Ops.exe" --create-admin admin
    Restart-Service RemoteDesktopOps

它会交互式地问口令，然后打印 TOTP 密钥与 otpauth:// 链接，用验证器扫码即可。
**密钥只显示这一次**，丢了只能再建一个账号。之后每次登录都要口令 + TOTP。
命令默认读写 %ProgramData%\Remote Desktop Server\Ops\appsettings.json，和服务是同一份配置。

监控台自己的配置在 Ops\appsettings.json（Ops:Listen、Ops:Database、Ops:NodeToken 等）。
对外访问由 Gateway 负责；Gateway 配置及其固定回环路由在 Gateway\appsettings.json。Ops 的
TrustedProxies 已自动加入 127.0.0.1，使 HTTPS Cookie、审计来源 IP 和登录失败限流使用真实客户端地址。
删掉 ops.db 只会丢掉监控历史、告警与审计，**不影响**远程桌面连接本身。


五、升级与卸载
--------------

- **升级/同版本重装**：直接安装新 MSI。ProgramData 下的设置、数据库和证书都会保留；
  安装命令行里的属性只在第一次安装时生效。
- **卸载**默认保留 ProgramData 下的数据库、设置、日志和生成的证书（重装后设备码不变）。
- 要连同数据与生成证书一起删除：
      msiexec /x RemoteDesktop-Server-Windows-x64-<版本>.msi /qn REMOVEDATA=1
  这会删除 %ProgramData%\Remote Desktop Server 和证书存储里由本产品生成的
  "RemoteDesktop Server (<机器名>)" 证书。
